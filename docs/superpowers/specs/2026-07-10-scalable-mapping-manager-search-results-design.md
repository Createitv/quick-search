# QuickSearch 可扩展映射管理与文件夹搜索页设计

## 目标

让一两百条甚至更多映射仍然容易查找和编辑，同时把多个关键词对应同一文件夹的关系压缩成一条清晰记录。首页继续作为真实文件夹搜索页，并扩大、压紧结果区域，让用户一次看到更多 Everything 搜索结果。

## 映射语义

QuickSearch 的底层关系仍然是关键词与文件夹路径之间的多对多关系：

- 一个关键词可以对应多个文件夹；触发后一起打开。
- 一个文件夹可以对应多个关键词；任意关键词都能触发该文件夹。
- 完全相同的关键词和路径只保留一项。

设置页不再把每个关键词路径对显示成独立行，而是按文件夹路径分组。一条设置记录包含：

- 一个文件夹路径。
- 一个逗号分隔的关键词文本。

例如：

```text
关键词：你好，今天好, hello
文件夹：D:\资料\问候语
```

保存后等价于三条底层映射：

```text
你好     → D:\资料\问候语
今天好   → D:\资料\问候语
hello    → D:\资料\问候语
```

同一个关键词仍可出现在另一条文件夹记录中，因此不会破坏一个关键词打开多个文件夹的能力。

## 关键词解析

关键词字段支持以下分隔符：

- 英文逗号 `,`
- 中文逗号 `，`
- 英文分号 `;`
- 中文分号 `；`
- 换行

解析时会：

1. 去掉每个关键词两侧空白。
2. 删除空项。
3. 使用现有 `AliasNormalizer` 折叠大小写和内部空白相同的重复关键词。
4. 保留用户输入顺序。
5. 在界面中统一用中文逗号和空格重新显示。

关键词本身如果确实需要包含逗号，不在本版本支持转义；这是为了让输入规则保持简单。

## 设置窗口结构

设置窗口默认尺寸扩大到约 `980 × 720`，最小尺寸保证表格和编辑区域可用。窗口分成两个页签：

### 通用设置

只包含：

- Everything 状态。
- 全局快捷键。
- 登录 Windows 后自动启动。

它不再和映射列表争夺垂直空间。

### 映射管理

映射管理页使用完整窗口内容区：

1. 顶部工具栏固定显示搜索框、“新建映射”和“删除所选”。
2. 搜索框实时匹配关键词文本或文件夹路径。
3. 工具栏显示“当前显示 N 条 / 共 M 条”。
4. 中间使用虚拟化表格，只创建屏幕内可见行。
5. 关键词列约占 40%，支持直接编辑逗号分隔文本。
6. 路径列约占 60%，支持直接编辑完整路径。
7. 表头固定，列表独立滚动。
8. 新建记录插入列表顶部并自动选中，不需要滚动到底部。
9. `Delete` 删除选中记录，`Ctrl+F` 聚焦映射搜索框。
10. 底部的取消和保存按钮始终固定，不跟随列表滚动。

不加入分页。对于一两百条本地记录，搜索和虚拟化表格比分页更快，也不会切断键盘操作。

## 过滤和编辑状态

设置页继续采用暂存式编辑：

- 打开设置时从当前配置创建文件夹分组。
- 搜索只改变可见记录，不改变待保存数据。
- 编辑、新增和删除只修改暂存分组。
- 点击“保存更改”时，把每个分组解析成底层关键词路径对，并一次性执行现有快捷键、开机启动和 JSON 配置事务。
- 点击“取消”恢复所有内容。
- 保存失败时不产生部分配置。

过滤期间删除只删除当前选中的真实分组，不依赖可见索引。清空过滤后仍能看到其他未匹配记录。

## 旧配置兼容

JSON 文件格式不改变。加载旧配置时：

1. 按不区分大小写的文件夹路径分组。
2. 收集指向该路径的所有关键词。
3. 设置页显示为一条逗号分隔记录。

保存时：

1. 解析所有分组得到目标关键词路径对集合。
2. 旧集合中仍存在的项保留原创建时间和最后使用时间。
3. 被删除的项移除。
4. 新项使用当前时间创建。
5. 完全重复项折叠。

因此不需要 schema 迁移，也不会丢失现有一对多或多对一映射。

## 首页真实文件夹搜索页

首页仍是统一启动器，同时明确呈现为真实文件夹搜索页：

- 默认尺寸调整为约 `840 × 720`，保留可自由缩放能力。
- 顶部保留单个 Everything 文件夹搜索框。
- 状态区域压缩，给结果列表更多垂直空间。
- 结果行改为紧凑的左右结构：左侧文件夹名称，右侧完整路径。
- 路径单行省略，鼠标悬停显示完整路径。
- 一屏目标显示约 10 到 12 条结果，超过部分使用滚动条。
- 搜索结果上限仍为 20 条。
- `↑`、`↓`、`Enter`、双击和 `Esc` 行为保持不变。
- Everything 只搜索文件夹，不增加递归磁盘扫描。
- 没有映射的剪贴板关键词仍会自动进入该搜索页。

主页面继续保留蓝到青的细路径光束作为 QuickSearch 的视觉识别元素，其余装饰服从结果密度。

## 组件设计

### `MappingGroupEditorViewModel`

新增文件夹分组编辑模型：

- `KeywordsText`：逗号分隔关键词。
- `FolderPath`：唯一文件夹路径。
- `ParseKeywords()`：返回规范化去重、保持顺序的关键词列表。
- 属性变化通知设置页刷新过滤结果和计数。

### `SettingsViewModel`

新增：

- `MappingGroups`：全部暂存文件夹分组。
- `FilteredMappingGroups`：当前过滤结果。
- `MappingFilter`：搜索文本。
- `VisibleMappingCountText`：当前和总数。
- 新建、删除命令改为操作分组。
- 保存候选配置改为比较目标关键词路径对集合。

现有事务回滚、Everything 健康状态和快捷键逻辑保持不变。

### WPF

- `SettingsWindow.xaml` 使用页签和虚拟化 `DataGrid`。
- `SettingsWindow.xaml.cs` 只负责 `Ctrl+F` 聚焦和新建后滚动到选中项，不承载业务规则。
- `MainWindow.xaml` 调整尺寸和结果行布局。
- 继续复用 `ModernTheme.xaml` 的颜色、字体、输入框、按钮和状态样式；只补充必要的页签与表格样式。

## 错误处理

- 某个分组没有关键词或路径：阻止保存并指出该记录。
- 两个分组使用同一路径：保存前合并为一个目标集合，不产生重复底层项；界面提示应合并记录。
- 同一关键词在同一分组内重复：自动折叠。
- 同一关键词出现在不同文件夹分组：合法。
- 过滤无结果：显示“没有匹配的映射”，保留搜索框和新建按钮。
- 路径过长：首页和映射表格均提供完整路径工具提示。

## 测试策略

跨平台单元测试覆盖：

- 各种分隔符解析、空白清理、顺序保留和重复折叠。
- 旧扁平映射按路径分组显示。
- 搜索同时匹配关键词和路径。
- 新建记录出现在顶部。
- 过滤状态下删除正确的真实分组。
- 多关键词同文件夹保存为多个底层映射。
- 同一关键词跨文件夹仍保留多个映射。
- 取消恢复全部分组。
- 保存失败回滚外部设置和配置。
- 两百条分组过滤计数正确。

最终验证包括全量核心测试、Windows WPF Release 零警告构建、格式检查、配置烟雾测试和 GitHub Actions 打包。

## 非目标

- 不增加 CSV 或 Excel 导入导出。
- 不增加分页。
- 不改变 JSON 配置 schema。
- 不增加文件搜索，只搜索文件夹。
- 不增加网络同步或云端映射。
