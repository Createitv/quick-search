# QuickSearch 树形规则资源管理器设计

## 产品目标

把主窗口从搜索表单改成文件夹式规则导航器。用户打开窗口后，先看到自己维护的分类结构和快捷规则；可以像使用资源管理器一样逐层进入文件夹，也可以从顶部收藏栏直接跳到任意常用分类。现有的关键词快捷打开和 Everything 文件夹搜索继续保留，分类层级只负责整理和导航，不改变既有打开语义。

本设计取代 2026 年 7 月相关规格中“首页保持纯 Everything 搜索页”和“配置 schema 不改变”的约束。原有 grouped mapping 交互、关键词分隔符、快捷打开语义和 Everything 搜索行为继续保留；首页信息架构和持久化模型以本设计为准。

## 核心概念

### 分类文件夹

分类文件夹是 QuickSearch 内部的组织结构，不对应磁盘上的真实目录。每个分类文件夹拥有稳定 ID、名称、父文件夹、同层排序和更新时间。父子关系不设置固定深度上限，但必须保持为无环树。

同一父文件夹内不允许重名；不同层级允许使用相同名称。移动分类文件夹时整个子树一起移动，且禁止移动到自身或自身后代中。

### 规则

一条规则代表一个可以快速打开的真实文件夹，包含：

- 稳定 ID。
- 可选的自定义标题；未填写时使用目标文件夹名称。
- 一个或多个关键词。
- 一个真实文件夹路径。
- 一个所属分类文件夹 ID。
- 同层排序。
- 创建、更新和最后使用时间。

一条规则只能属于一个真实分类位置。同一目标路径只保留一条规则；再次添加相同路径时，界面定位到现有规则，并允许把新关键词合并进去。同一关键词仍然可以存在于多条不同路径的规则中，因此现有“一条关键词打开多个文件夹”的能力不变。

### 顶部收藏

顶部收藏只保存分类文件夹 ID 的有序列表，不复制文件夹或规则。任意层级的分类文件夹都能 Pin；拖拽只改变收藏栏的左右顺序，不改变真实分类位置。删除分类文件夹时同步移除对应 Pin。

## 主窗口信息架构

主窗口采用已确认的“树形资源管理器”结构：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ [⠿ 小溪] [⠿ EPSTEC] [⠿ 100 Apps] [⠿ 开发资料] [+]                │
├──────────────────┬───────────────────────────────────────────────────┤
│ 全部文件夹     + │ 客户 › 小溪 › 项目 › QuickSearch   [搜索… Ctrl K]│
│ ▾ 客户            │                                                   │
│   ▾ 小溪       ★ │ 子文件夹                                          │
│     ▾ 项目        │ [设计] [开发] [构建产物] [归档]                   │
│       QuickSearch │                                                   │
│       FastAPI     │ 当前文件夹的规则                                  │
│   EPSTEC       ★ │ Quick Search 代码    F:\…\quick-search    打开 → │
│ ▸ 个人项目        │ 设计文档             F:\…\docs            打开 → │
│ ▸ 资料库          │                                                   │
├──────────────────┴───────────────────────────────────────────────────┤
│ Esc 隐藏  ·  单击规则直接打开       Everything 就绪              ⚙ │
└──────────────────────────────────────────────────────────────────────┘
```

### 顶部收藏栏

- 收藏栏是窗口内容的第一层，不再显示页面内的 `QuickSearch` 标题或“复制邮箱别名”说明。
- 文件夹以紧凑标签显示，包含拖拽把手、文件夹图标和名称。
- 单击收藏项进入该分类；当前分类使用蓝色选中态。
- 横向空间不足时使用水平滚动，不换行挤压内容区。
- 拖拽改变左右顺序并立即保存；保存失败时恢复原顺序并显示明确错误。
- `+` 只打开收藏选择器，不创建新的分类文件夹。

### 左侧目录树

- 根节点是只读的“全部文件夹”虚拟节点。
- 子节点按同层排序展示，可逐层展开和折叠。
- 当前文件夹使用浅蓝背景、蓝色文字和可见焦点状态。
- 已 Pin 的文件夹显示星标，但仍只存在于一个真实层级位置。
- 单击文件夹切换右侧内容；双击或展开箭头控制展开状态。
- 键盘支持 `↑`、`↓` 移动，`←` 收起或进入父级，`→` 展开，`Enter` 进入。

### 右侧内容区

- 顶部左侧显示完整面包屑，任一父级都可点击返回。
- 顶部右侧常驻紧凑搜索框；窗口激活时不强制夺取目录树焦点。
- 当前分类的子文件夹先以文件夹卡片网格展示，规则再以高密度列表展示。
- 文件夹卡片显示名称，以及子文件夹或规则数量。
- 规则行显示标题、目标路径和“打开”反馈；路径过长时单行省略，悬停显示完整路径。
- 单击规则行或在聚焦规则时按 `Enter` 立即打开目标文件夹。
- 文件夹双击进入；搜索结果继续支持方向键、`Enter` 和双击打开。

### 底部状态栏

- 左侧只保留 `Esc 隐藏` 和当前可用操作提示。
- 右侧显示 Everything 状态和固定的小齿轮设置按钮。
- 第一次按 `Esc` 清除搜索并返回原分类；没有搜索状态时再按 `Esc` 隐藏窗口。
- 系统窗口标题文字置空，只保留标准最小化、最大化和关闭按钮。

## 搜索与快速打开

搜索框始终只有一个，不再弹出第二套搜索表单。

### 本地规则搜索

点击搜索框或按 `Ctrl+K` 后输入，先在本地索引中匹配：

- 规则自定义标题。
- 规则关键词。
- 规则目标文件夹名称和完整路径。
- 分类文件夹名称和完整分类路径。

输入使用短防抖，右侧内容区切换为搜索结果，目录树和顶部收藏保持可见。结果分为“分类文件夹”和“规则”，并显示完整分类路径，避免同名项混淆。清空搜索后回到开始搜索前的分类位置和树展开状态。

### Everything 搜索回退

本地没有匹配项时，结果区显示明确操作“用 Everything 搜索磁盘”。点击该操作或在它被选中时按 `Enter`，复用现有 Everything 文件夹搜索：

- 最多显示 20 个真实文件夹结果。
- `↑`、`↓` 移动选择。
- `Enter` 或双击打开结果。
- 搜索错误、Everything 未运行和无结果继续使用现有可恢复状态。
- 从 Everything 结果返回时保留用户输入，方便修改关键词。

普通 Everything 搜索结果不会自动创建规则。规则仍然只能在明确的管理操作中保存。

### 关键词快捷打开

现有剪贴板和全局快捷键流程保持不变：

1. 复制关键词后按全局快捷键。
2. 关键词命中一条或多条规则时，直接打开所有有效目标路径，不显示确认表单。
3. 没有规则命中时，显示主窗口并以该关键词进入搜索状态。
4. 部分路径失效时打开仍有效的路径，同时显示错误和 Everything 回退入口。
5. 成功打开后保留现有最后使用时间更新逻辑。

## 首页轻管理

首页只提供低风险、高频操作：

- 顶部收藏项拖拽排序。
- 文件夹右键菜单中的“新建子文件夹”。
- 文件夹重命名。
- Pin 或取消 Pin。

这些操作对配置克隆执行校验后立即保存。成功后显示短暂的撤销提示；撤销会执行一次反向保存。保存失败时界面恢复操作前状态，不留下部分修改。

首页不提供删除分类、跨层移动、批量移动规则或编辑规则内容。这些操作统一进入设置页，避免把快速打开界面变成重型管理器。

## 设置页完整管理

齿轮打开设置窗口。通用设置继续管理 Everything、全局快捷键和开机启动；分类与规则使用独立管理页：

- 左侧为完整分类树，支持新建、重命名和拖拽移动整个子树。
- 右侧显示当前分类的规则，支持新建、编辑、删除、多选和批量移动。
- 规则编辑包含标题、关键词列表、真实文件夹路径和所属分类。
- 关键词继续支持中文逗号、英文逗号、中文分号、英文分号和换行分隔。
- 设置页内所有复杂修改只操作暂存配置，点击“保存更改”后一次性提交；“取消”恢复打开设置前的状态。

删除空分类可以直接确认。删除非空分类必须明确选择：

1. 把直接内容移动到上一级后删除分类。
2. 连同全部子分类和规则删除。
3. 取消。

第一项的精确行为是：当前分类中的直接规则改为归属父分类，当前分类中的直接子文件夹改为以父分类为父节点；子文件夹内部的后代结构保持不变，不把整个子树扁平化。顶级分类执行该操作时，内容移动到“未分类”。第二项必须展示将删除的子分类数和规则数，不使用模糊的通用确认文案。

## 持久化模型

配置 schema 升级为版本 2，版本号继续存放在现有的 `AppSettings.SchemaVersion`。逻辑结构如下：

```text
AppConfiguration
├── Settings
├── NavigationFolders[]
│   ├── Id
│   ├── ParentId
│   ├── Name
│   ├── SortOrder
│   └── UpdatedAtUtc
├── Rules[]
│   ├── Id
│   ├── Title
│   ├── Aliases[]
│   ├── FolderPath
│   ├── NavigationFolderId
│   ├── SortOrder
│   ├── CreatedAtUtc
│   ├── UpdatedAtUtc
│   └── LastUsedAtUtc
└── PinnedFolderIds[]
```

所有 ID 使用持久化的稳定 GUID。数组顺序不作为业务顺序真相；分类和规则使用显式 `SortOrder`，收藏栏使用 `PinnedFolderIds` 的列表顺序。

配置保存继续使用临时文件加原子替换。所有层级、唯一性、路径和 Pin 引用校验在写盘前完成；任何校验或外部设置失败都不写入部分配置。

## 旧配置迁移

版本 1 的扁平 `FolderMapping` 在加载时迁移到内存中的版本 2：

1. 创建不可删除的顶级分类“未分类”。
2. 按大小写不敏感的目标文件夹路径对旧映射分组。
3. 每个路径分组生成一条规则，关键词按旧配置顺序收集并规范化去重。
4. 标题默认使用目标路径最后一个有效目录名；无法取得名称时使用完整路径。
5. 创建时间取分组内最早值，更新时间和最后使用时间分别取最新值。
6. 所有迁移规则归入“未分类”，Pin 列表初始为空。

仅加载旧配置不会立即覆盖原文件。第一次执行首页轻管理或设置页保存时，才以原子写入方式持久化版本 2。迁移不会改变 `关键词 → 一个或多个真实文件夹` 的查询结果。

## 组件边界

### 核心模型

- `NavigationFolder`：保存分类节点数据，不包含 UI 展开状态。
- `FolderRule`：保存规则标题、关键词、真实路径、分类和使用时间。
- `AppConfiguration`：维护树结构、规则、Pin 顺序和跨模型约束。
- `ConfigurationMigrator`：只负责版本 1 到版本 2 的确定性迁移。

### 主窗口状态

- `RuleExplorerViewModel`：目录树、当前分类、面包屑、收藏栏、本地搜索、首页轻管理和撤销。
- `LauncherViewModel`：继续负责快捷键激活、Everything 搜索、结果选择、打开路径和状态消息，并组合 `RuleExplorerViewModel`。
- `MainWindow.xaml`：只声明顶部收藏、左侧树、右侧内容状态和底部状态栏。
- `MainWindow.xaml.cs`：只处理窗口激活、需要 WPF 事件支持的拖拽和焦点转移，不承载层级业务规则。

### 设置状态

- `SettingsViewModel`：持有配置克隆和事务式保存流程。
- `NavigationOrganizerViewModel`：管理暂存分类树、规则列表、拖拽移动和删除影响统计。
- `SettingsWindow.xaml`：通用设置和分类规则管理页，不复制核心校验逻辑。

## 状态与错误处理

- 真实路径不存在：规则显示警示标记；打开时不启动无效路径，并提供 Everything 重新查找入口。
- 同一父级分类重名：阻止保存并聚焦冲突名称。
- 目标路径重复：定位到已有规则，允许合并新关键词，不创建第二条规则。
- 循环移动：在模型层拒绝，界面保持原树位置。
- 非空删除：必须经过三选一删除流程。
- Pin 指向被删除分类：在同一事务中移除，不留下悬空引用。
- 首页即时保存失败：恢复操作前状态并保留可重试错误。
- Everything 不可用：本地规则导航仍可使用，状态栏显示可恢复错误。
- 打开多个关键词目标时部分失败：成功项照常打开，失败路径汇总显示。

## 视觉系统

继续使用 Path Beam 的浅色 Windows 桌面视觉语言：

- 画布 `#F3F6FB`，内容面 `#FFFFFF`，主文字 `#162033`，次文字 `#667085`。
- 路径蓝 `#2F6BFF` 和信号青 `#36C5E5` 只用于当前树节点、Pin、焦点、状态和打开反馈。
- 标题使用 `Segoe UI Variable Display`，正文和控件使用 `Segoe UI Variable Text`，回退到 `Segoe UI`。
- 使用真实文件夹形状图标，不用彩色 emoji。
- 主界面不再套一层巨大的装饰卡片；窗口内容直接形成顶部栏、目录树、内容区和状态栏。
- 不使用持续动画或亚克力透明。悬停、展开和打开反馈控制在约 120–160 毫秒，并尊重系统减少动画设置。
- 窗口缩小时目录树保持最低可用宽度，右侧文件夹网格自动减少列数，规则路径优先省略而不挤掉标题和打开操作。

## 非目标

- 不自动把磁盘目录结构导入分类树。
- 不允许一条规则拥有多个真实分类位置；跨分类访问依靠搜索。
- 不 Pin 单条规则，只 Pin 分类文件夹。
- 不在首页提供删除、跨层移动、批量整理和规则内容编辑。
- 不改变 Everything 为“只搜索文件夹”的范围。
- 不增加网络同步、多人协作、标签系统、CSV 或 Excel 导入导出。
