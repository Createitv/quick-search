# QuickSearch 统一启动器与一对多映射设计

## 目标

把现有“邮箱别名到单个文件夹”的确认式启动器，简化为一个统一的关键词启动器：关键词已有映射时直接打开全部绑定文件夹；没有映射时自动进入 Everything 文件夹搜索；剪贴板为空时允许用户直接输入搜索。

## 核心交互

### 全局快捷键

用户按现有全局快捷键后，程序读取剪贴板文本并规范化关键词：

1. 剪贴板有关键词，且关键词存在一个或多个有效映射：直接打开所有绑定文件夹，不显示确认窗口。
2. 剪贴板有关键词，但不存在映射：显示启动器，把关键词填入搜索框，并自动通过 Everything 搜索文件夹。
3. 剪贴板为空：显示启动器，清空并聚焦搜索框，等待用户输入。
4. 部分映射路径失效：打开仍然有效的路径，同时显示启动器并提示失效路径；不自动删除配置。
5. 所有映射路径均失效：显示启动器并使用该关键词执行 Everything 搜索，便于用户继续查找。

映射命中后不再显示确认窗口，也不要求用户再次按 Enter。

### 启动器窗口

启动器只保留一个主要输入框和一个文件夹结果列表：

- 输入框内容就是 Everything 文件夹搜索词，不再区分“别名”和“真实文件夹名称”两个输入框。
- 输入变化后进行短暂防抖并自动搜索；也保留显式搜索命令供键盘操作调用。
- 最多显示 20 个文件夹结果，展示文件夹名称和完整路径。
- `↑`、`↓` 在结果中移动选择；首次有结果时默认选中第一项。
- `Enter` 打开当前选中的单个搜索结果。
- 双击结果与 `Enter` 行为一致。
- `Esc` 隐藏窗口。
- 打开搜索结果不会自动创建映射。映射只在设置页中明确管理，避免误保存。

窗口状态文案只说明当前动作，例如“找到 8 个文件夹”“Everything 未运行”“未找到文件夹”，不再使用邮箱专属文案。

## 一对多映射模型

继续使用扁平的 `FolderMapping` 列表，每一项仍然是一个 `关键词 + 文件夹路径`。同一规范化关键词允许出现多项，从而自然形成一对多关系。

### 唯一性

- 允许：同一关键词绑定不同文件夹。
- 允许：不同关键词绑定同一文件夹。
- 禁止：规范化关键词和文件夹路径都相同的完全重复项。
- 路径比较在 Windows 上按大小写不敏感处理。

### 兼容性

现有 JSON 配置结构无需迁移。旧配置中的每个一对一映射在新版本中自然成为只有一个目标的一对多映射。加载配置时不再按关键词去重，只去除完全重复的 `关键词 + 路径` 项，因此已有数据不会丢失。

### 使用时间

成功打开映射后，更新该关键词下所有成功打开项的最后使用时间。某个路径打开失败不会阻止其他有效路径继续打开。

## 设置页

设置页继续使用可编辑映射列表，并明确改为“关键词映射”：

- “新建映射”新增一行空白的关键词和文件夹路径。
- 用户可添加多行相同关键词，分别填写不同路径。
- 每一行可独立编辑、选择和删除。
- 保存时校验关键词与路径非空，并阻止完全重复项。
- 保存是事务式的：快捷键、开机启动或映射校验失败时，不写入部分配置。

第一版不增加文件夹选择器，也不在设置页嵌入 Everything 搜索。用户可直接粘贴完整路径；这样能复用现有界面并保持实现简单。启动器中的 Everything 搜索负责日常快速打开，设置页只负责稳定映射。

## 组件调整

### `AppConfiguration`

- `FindMappings(keyword)` 返回该关键词的全部映射。
- 新增映射时按 `关键词 + 路径` 去重，不再覆盖该关键词的旧路径。
- 更新和删除操作以单个映射项的稳定标识为目标，避免编辑同名关键词时误改其他行。

为兼容旧配置，稳定标识不写入 JSON；设置编辑会保留原始关键词和原始路径作为行定位键。完全重复项在加载时折叠。

### `LauncherViewModel`

统一管理快捷键激活、Everything 搜索、结果选择和打开：

- `ActivateFromClipboardAsync` 负责映射优先决策。
- 映射命中时依次打开全部有效目标并持久化使用时间。
- 未命中时把剪贴板文本设为搜索词并执行搜索。
- 常规搜索只打开结果，不写入映射。

### Windows 窗口层

- 快捷键和单实例激活改为调用异步激活流程。
- 窗口只在需要搜索、输入或显示错误时出现。
- 键盘选择使用现有 WPF `ListBox` 选择行为和命令绑定，不引入新 UI 框架。

## 错误处理

- Everything 不可用：保留搜索词并显示可恢复错误，用户可启动 Everything 后重试。
- 剪贴板读取失败：显示空白启动器和错误，不保留上一次搜索造成误开。
- 多路径打开部分失败：成功路径照常打开，失败路径汇总成一条状态信息。
- 配置保存失败：已经打开的文件夹不回滚，但明确提示使用时间未保存。
- 搜索被新输入替代：取消旧请求，旧结果不得覆盖新关键词的结果。

## 测试策略

核心行为全部通过跨平台单元测试覆盖：

- 同一关键词可保存并读取多个路径。
- 完全重复映射被拒绝或折叠，旧一对一 JSON 正常加载。
- 编辑或删除单行不会影响同关键词的其他映射。
- 快捷键命中一对多映射时直接打开全部有效路径且不请求显示窗口。
- 部分或全部路径失效时按设计降级。
- 无映射时使用剪贴板关键词自动搜索。
- 空剪贴板显示空白启动器。
- 搜索结果默认选择第一项，打开结果不创建映射。
- 搜索取消、Everything 错误和打开失败状态正确。

最终验证包括 103 项现有回归测试、新增测试、Windows WPF Release 零警告构建、配置烟雾测试和 GitHub Actions Windows 打包。

## 非目标

- 不增加第二套全局快捷键。
- 不支持文件搜索，只搜索文件夹。
- 不把普通搜索结果自动保存为映射。
- 不增加映射确认窗口或模式切换。
- 不增加网络同步、云配置或邮件服务集成。
